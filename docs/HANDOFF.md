## 1. Что за проект и почему такой

Третья учебная работа. Первая — Telegram-бот, вторая — сайт. Нужно «не хуже», плюс свой
git-репозиторий и **итоговый коммит каждый день**.

Выбран **Tower Defense с пиксель-артом**, потому что:

* заведомо сложнее бота и сайта: игровой цикл, поиск пути, ИИ целей, баланс, сохранения;
* **полностью офлайн** — критично, так как на компьютерах колледжа нельзя настроить прокси,
  а значит недоступны Telegram API и любые внешние сервисы;
* запускается двойным кликом по `index.html`, ничего устанавливать не нужно.

### Ключевые ограничения (не нарушать)

| Ограничение | Следствие |
|---|---|
| Нет интернета | никаких CDN, шрифтов из сети, внешних API |
| Нельзя ставить софт | нет npm-зависимостей, нет сборки (webpack/vite), нет Python/pygame |
| `file://` в браузере | **нельзя** ES-модули (`import`) — Chrome блокирует их по CORS. Только классические `<script>` с глобальным неймспейсом `TD` |
| Ассеты только локальные | тайлсет, объекты и анимации башен/монстров лежат рядом с `index.html`; звук — синтез через WebAudio |
| Браузер может запретить localStorage на `file://` | все обращения к `localStorage` — в `try/catch`, при ошибке игра работает без сохранений |

## 2. Стек и структура

Чистый HTML + CSS + JavaScript (ES2019, без модулей). Canvas 2D.

```
index.html            — разметка, экраны меню, подключение скриптов (порядок важен!)
css/style.css         — вся вёрстка и оформление
js/core/util.js       — неймспейс TD, математика, RNG, форматирование
js/core/sprites.js    — процедурный пиксель-арт: строки-палитры → offscreen canvas
js/core/assets.js     — загрузка тайлсета, объектов и анимаций трёх наборов
js/core/menu-scene.js — анимированная сцена главного меню
js/core/audio.js      — синтез звуков на WebAudio (без файлов)
js/data/maps.js       — 6 карт в виде ASCII-строк 28×17
js/data/defs.js       — конфигурация, таблицы башен и врагов (баланс)
js/data/waves.js      — генератор 12 волн
js/logic/grid.js      — сетка, A*, проверка «путь не перекрыт»
js/game.js            — класс Game: состояние, update(dt), render(ctx), ввод
js/ui.js              — экраны, HUD, магазин, инспектор, сохранения, бестиарий
js/main.js            — бутстрап и отладочный автозапуск
free-fields-tileset-pixel-art-for-tower-defense/ — поле и объекты (CraftPix)
free-archer-towers-pixel-art-for-tower-defense/  — башня, апгрейды, лучник
free-field-enemies-pixel-art-for-tower-defense/  — анимации монстров
tests/run.js          — 32 теста логики на Node (без браузера)
tools/balance.js      — симуляция баланса ботом
tools/ui-check.js     — проверка интерфейса через DevTools Protocol
docs/screenshots/     — скриншоты для README
docs/                 — эта документация
```

Порядок подключения скриптов в `index.html` уже задан — менять только осознанно:
`util → sprites → assets → menu-scene → audio → maps → defs → waves → grid → game → ui → main`.

### Ассеты

Используются три набора CraftPix (условия в `License.txt` /
https://craftpix.net/file-licenses/):
* **free-fields** — тайлы поля и объекты (камни, деревья, трава, цветы, лагеря, заборы,
  фонари, флажки, анимированные костры и флаги);
* **free-archer-towers** — кадровые анимации башни по уровням, апгрейд и лучник
  (idle/attack);
* **free-field-enemies** — ходьба монстров в трёх направлениях и смерть (4 вида).

`js/core/assets.js` грузит PNG по относительным путям (работает и на `file://`);
при отсутствии файлов используется процедурный фолбэк. Портал, сердце и часть
эффектов остаются процедурными спрайтами. Объекты рисуются в натуральном или
целочисленном масштабе (1×/2×/3×), чтобы пиксели не «плыли»; у башен цветная
крыша и эмблема типа (стрела, пушка, снежинка, молния, прицел).

### Принцип разделения

`Game` **не знает про DOM и canvas**: он получает размеры и отдаёт состояние. Отрисовка —
отдельный метод, принимающий `ctx`. Это позволяет гонять игровую логику в Node без браузера
(тесты и симуляция баланса).

## 3. Игровая механика

### Карта

Сетка **28 × 17** клеток, клетка **52 px**, canvas **1456 × 884**. Сетка задаётся ASCII-картой,
легенда:

| Символ | Значение |
|---|---|
| `.` | трава, можно строить |
| `,` | утоптанная земля, можно строить (декор) |
| `#` | скала, строить нельзя |
| `~` | вода, строить нельзя |
| `S` | портал (спавн) |
| `B` | сердце (база) |

Шесть карт: «Перевал» (открытая), «Ущелье» (камни, узкие проходы), «Болото» (вода,
извилистый маршрут), «Чаща» (лесные завалы), «Крепость» (каменные дворы) и «Пепел»
(выжженная пустошь).

### Ключевая фишка — площадки под башни

Башни можно ставить **только на фиксированные площадки** — по 18 на карту. Площадки
генерируются детерминированно из маршрута: берутся клетки у дороги, разнесённые друг
от друга, чтобы каждая башня имела зону обстрела, но застроить всё поле было нельзя.
Одна площадка — одна башня; продажа освобождает её.

Это решает две задачи: не даёт спамить башнями и не позволяет замуровать маршрут.
Маршрут фиксируется один раз при старте уровня — постройка и продажа башен не меняют
дорогу и путь врагов.
A* по-прежнему считает путь от портала к сердцу, а проверка `canPlace` остаётся
страховкой: площадки никогда не стоят на дороге.

Движение — по 4 направлениям (без диагоналей, чтобы не было «протечек» сквозь углы).

Летающие враги игнорируют дорогу и летят по прямой от портала к сердцу — против них нужны
башни с флагом `air: true`.

### Башни (цены и характеристики — стартовые, требуют подгонки)

| # | Башня | Цена | Урон | Радиус | Скорость | Особенность | По воздуху |
|---|---|---|---|---|---|---|---|
| 1 | Стрелок | 50 | 8 | 3.2 | 1.6/с | одиночная цель | да |
| 2 | Пушка | 90 | 22 | 3.0 | 0.7/с | сплэш 1.2 клетки | нет |
| 3 | Криомант | 70 | 3 | 2.6 | 1.2/с | замедление 40% на 1.5 с | да |
| 4 | Тесла | 130 | 12 | 2.8 | 1.0/с | цепь на 3 цели | да |
| 5 | Снайпер | 160 | 90 | 7.0 | 0.45/с | игнорирует броню | да |

Улучшения: 3 уровня, каждый +25% урона, +10% радиуса, цена ≈ 80% от базовой за уровень.
Продажа — 60% вложенного (база + улучшения).

Режимы цели (переключаются в инспекторе): `первая` (дальше всех прошедшая путь),
`сильная` (макс. HP), `ближняя` (минимальная дистанция).

### Враги

| Тип | HP | Скорость (клеток/с) | Броня | Золото | Очки | Примечание |
|---|---|---|---|---|---|---|
| slime | 40 | 1.1 | 0 | 4 | 10 | базовый |
| runner | 25 | 2.2 | 0 | 5 | 12 | быстрый |
| swarm | 15 | 1.6 | 0 | 2 | 5 | идут толпой |
| brute | 160 | 0.8 | 2 | 12 | 30 | танк |
| shield | 120 | 0.9 | 6 | 14 | 35 | высокая броня |
| flyer | 60 | 1.4 | 0 | 8 | 20 | летит по прямой, игнорирует дорогу |
| boss | 1500 | 0.6 | 5 | 120 | 400 | на 6-й и 12-й волне, при смерти делится на 3 brute |

Масштабирование HP: `baseHp * (1 + 0.16 * (wave - 1)) * (1 + 0.10 * индекс_уровня)`.
Броня вычитается из урона, но не ниже 1 (кроме снайпера, который её игнорирует).
Коэффициенты подобраны симуляцией `tools/balance.js`: при 12 волнах и 18 площадках
бот проходит все шесть карт, теряя 8–12 жизней.

### Экономика и волны

* Старт: **360 золота**, **20 жизней**.
* 12 волн на уровень, состав генерируется детерминированно (seed = индекс уровня + номер волны).
* Досрочный запуск волны: бонус `10 + 2 * номер волны` золота.
* За волну — награда `30 + 7 * номер`.
* Ранние волны ограничены по числу врагов (8 / 11 / 14 на 1–4-й волнах), чтобы после
  стартовых 360 золота игрок успевал занять площадки на любой карте.
* Дошёл до сердца: −1 жизнь (босс −5).
* После 12-й волны — победа.

## 6. Тесты и проверка без ручного клика

Логика отделена от DOM, поэтому:

```bash
node tests/run.js          # 32 юнит-теста логики, ассетов и площадок
node tools/balance.js      # бот-симуляция баланса (все 6 карт)
node tools/ui-check.js     # 31 проверка интерфейса в headless Chrome/Edge
```

`tools/ui-check.js` сам запускает браузер через DevTools Protocol, кликает по меню,
магазину и canvas, проверяет постройку/улучшение/продажу, волну, паузу, сохранение,
экран результата и падает при любой ошибке в консоли. Если Chrome/Edge не найден,
проверка завершается с кодом 2 и подсказкой.

Скриншоты интерфейса снимаются headless-браузером:

```powershell
& "C:\Program Files\Google\Chrome\Application\chrome.exe" --headless=new `
  --screenshot="shot.png" --window-size=1400,900 `
  --virtual-time-budget=4000 "file:///C:/путь/index.html?test=1&level=0&ff=300&demo=1"
```

Параметры автозапуска: `test=1`, `level` (0–2), `wave` / `waveNum`, `ff` (шаги по 1/30 с),
`demo=1` (демо-башни), `path=1` (показать путь).

## 7. Сохранения

`localStorage`, ключ `td_save_v1`:

```json
{
  "unlocked": 1,
  "best": { "0": { "score": 0, "waves": 0, "win": false } },
  "settings": { "sound": true, "grid": true, "path": false }
}
```

Все чтения/записи — через `try/catch`: на `file://` в некоторых конфигурациях браузера
localStorage недоступен, игра должна продолжать работать.

## 8. Риски и как их обходить

| Риск | Решение |
|---|---|
| ES-модули не грузятся с `file://` | только классические скрипты (уже учтено) |
| localStorage заблокирован | `try/catch` + игра без сохранений |
| WebAudio не стартует без жеста | инициализировать звук по первому клику |
| Папка с ассетами потерялась | `TD.Assets.get()` возвращает `null`, рендер откатывается на цветной фолбэк |
| Игрок замуровывает проход | проверка A* перед постановкой (реализована) |
| Баланс «непроходим» или «слишком легко» | симуляция в Node + правка таблиц; бот проходит все карты |
| Долгая загрузка спрайтов | всё генерируется один раз при старте, спрайты кэшируются |
| Панель не влезает в экран ноутбука | масштаб подгоняется под окно в `fitLayout()` |
| `localStorage` на `file://` | все операции в `try/catch`, тест проверяет работу без него |

## 9. Git

Репозиторий инициализирован локально, ветка `main`. История:

```
chore: каркас проекта «Пиксельная Оборона» и документация
docs: раздел про git и порядок переноса проекта
feat: игра целиком — карты, башни, волны, интерфейс, тесты
```

Автор коммита выставлен заглушкой (`student <student@localhost>`), потому что git
не был настроен. Перед первым push заменить на свои данные:

```bash
git config user.name  "Имя Фамилия"
git config user.email "you@example.com"
git commit --amend --reset-author --no-edit
```

Добавить remote и запушить (ссылка своя):

```bash
git remote add origin https://github.com/USER/REPO.git
git push -u origin main
```

Если remote уже есть — просто `git remote set-url origin ...`.

Правило «итоговый коммит каждый день»: в конце каждого дня работы один содержательный
коммит, например `feat: сетка, A* и проверка застройки`. Полезные префиксы:
`feat:`, `fix:`, `style:`, `docs:`, `test:`, `chore:`.

> При переносе на флешку копировать папку **целиком вместе со скрытой `.git`**,
> иначе история коммитов потеряется.
